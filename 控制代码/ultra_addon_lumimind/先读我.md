# 单台 ultra + 五通道灯控扩展

本包需要同事已有的 LumiMind agent 主体及其可用 Python 环境，不包含整个 agent 或 AI 密钥。
适用 Windows 10/11 x64、Python 3.11 x64、可用 BLE 适配器、.NET Framework 4.7.2 或更高版本。
无需 D:\Code、launcher.exe、MQTT/Mosquitto、InfluxDB、Docker、Node.js 或额外网页服务。
AI 仍使用同事原有的模型配置；附带离线包仅用于新增蓝牙依赖，不用于重建整个 agent 环境。

## 同事安装步骤

1. 把压缩包解压到任意目录，先停止正在运行的 agent。下面以 E:\lumimind 为同事 agent 根目录，按实际路径替换。
2. 在解压目录打开 PowerShell，用 agent 现有的 Python 安装蓝牙依赖（离线包适用 Python 3.11 x64）：

```powershell
& 'E:\lumimind\.venv\Scripts\python.exe' -m pip install --no-index --find-links .\wheels -r .\requirements-addon.txt
& 'E:\lumimind\.venv\Scripts\python.exe' .\install_ultra_addon.py --agent-root 'E:\lumimind'
& 'E:\lumimind\.venv\Scripts\python.exe' .\install_ultra_addon.py --agent-root 'E:\lumimind' --apply
```

首条命令不访问互联网；脚本第二条只预览，第三条执行。脚本核对文件指纹，修改已有文件前保存在 agent 根目录的 ultra_addon_backup_时间戳/。已有灯具、传感器配置保留，不覆盖。
如果提示 Custom/different file detected，说明同事的入口有自己的修改。脚本会在写入任何文件前停止，请按后面的手工接入说明合并，不能直接覆盖。
若同事 Python 不是 3.11 x64，使用他的环境联网安装 `python -m pip install --index-url https://pypi.org/simple -r requirements-addon.txt`，本包的原生离线 wheel 不适用其他 Python 版本。

3. 编辑 agent 根目录 `light_control/light_config.json`，把 `lamp_ip` 的 null 改为实际灯具 IPv4 字符串，例如 `"192.168.1.123"`（此地址仅为格式示例）。保留实际对应的 room_id、SDK 和标定文件。传感器默认配置为 ULTRA-004 / F6:2B:AC:6B:FC:66，如果换设备则修改 `ultra_monitor/config.json`。
4. 确认 ultra 已供电、Windows 蓝牙已开启，退出其他连接同一 ultra 的软件。灯具需要与电脑网络可达。传感器放在要观察照度的位置，求解标定条件不同可能使实测值不同。
5. 双击 agent 根目录 `start_ultra_agent.cmd`，或在 agent 的 backend 目录用已有 Python 运行：

```powershell
& '..\.venv\Scripts\python.exe' -m uvicorn app.main:app --host 127.0.0.1 --port 8000 --workers 1
```

仅启动一个 worker，不加 --reload，不同时启动第二个 agent 进程或 launcher，以免争用同一蓝牙设备。
启动后自动扫描、连接、采集，初次数据通常要等待扫描连接及至少一轮测量。停止 agent 时自动取消采集、释放连接。

6. 打开 `http://127.0.0.1:8000/page/chat`，输入“请将当前灯光调到 4000K、300 lx”。agent 输出明确目标后自动调用灯控模块；网页显示下发状态。普通知识问答不应触发调光。
7. 打开 `http://127.0.0.1:8000/ultra/dashboard` 查看实测。页面显示照度、CCT、设备支持的附加指标、连接状态、实测时间及最近 1/6/24 小时趋势。缺失指标显示“—”，不填造数值。

## 工作方式与边界

- ultra 协议提取自原监测系统的 BLE 采集代码，保留全部 notify 订阅及光谱/频闪触发；没有复制 Pro、Well 或完整原 dashboard。
- 测量触发间隔默认 12 秒；数据库记录触发时间和收到有效光学数据的时间，均为 UTC，网页按电脑本地时区显示。不是逐秒测量。
- 采集与灯控独立运行。断线会自动重连；无有效光学数据会重连，不会把上一轮数据当作新数据保存。缺失 BLE 驱动、设备未开机等错误显示在页面。
- 历史存在 `ultra_monitor/data/ultra.db`，默认在新数据写入时清理 30 天前记录。重启后可查看历史；“最近一次调光”只保留本次进程内记录。
- 照度/CCT 来源于硬件；目标、SDK 预测、UDP 已发送、传感器实测分别显示。系统不判定是否达标、不根据误差自动调整。
- SDK/参数错误或未填写灯具 IP 时不发送报文。每条有效目标调用一次灯控，不自动重发。UDP 无执行回执，网络错误不等同于灯具断电。
- AI 需按程序提示输出唯一 `lumimind-light` JSON 块；没有该块或格式不正确则不会猜测文本数字控制灯具。模型不遵循格式时，查看聊天错误并调整提问/模型，不把普通文字解析成控制命令。
- 包含房间 1 原始标定文件；换灯具、测量位置、距离或房间条件时应使用匹配标定，本次没有进行同事现场标定。
- 页面本身无外部 CDN、字体或图表依赖，可离线展示。AI 调用是否联网取决于原 agent 配置。

## 自定义 agent 的手工接入

不要用 payload/backend 或 payload/fontend 覆盖自定义文件。仅把 payload/ultra_monitor、payload/light_control 复制到 agent 根目录（已有灯控配置及 SDK 请先核对保留）。安装依赖后：

在后端应用创建后、兜底 `app.mount("/", ...)` 前增加：

```python
from ultra_monitor.integration import register_ultra
register_ultra(app)
```

确保 agent 根目录在 Python 导入路径中（原 backend/app/main.py 已有）。扩展使用 lifespan 包裹之前的生命周期；请在其他 lifespan 配置之后注册，且只运行一个 worker。

生成回答时把规则加入 system 提示词，返回后处理：

```python
from ultra_monitor.lighting import CONTROL_INSTRUCTION, lighting_service
# 传给原有模型的 system = 原 system + "\n" + CONTROL_INSTRUCTION
processed = await lighting_service.process(model_reply)
# 返回 processed["reply"], processed["lighting_target"], processed["lighting"]
```

响应模型需声明可选 lighting_target 和 lighting 字段；前端显示 lighting.message/error/status。
聊天入口要保留一份 router 和处理函数，避免原始文件重复定义覆盖接入逻辑。
仅当确实要执行调光时调用 process；若同事直接已有结构化目标，可直接调用 `light_control.lumimind_light.set_light(lux, cct)`，在异步接口中使用 `asyncio.to_thread`。

## 验证与恢复

安装后先查看 dashboard 的连接状态，再在实际灯具 IP 配置完成后发起一次目标调光，观察 ultra 是否持续更新。这一步需要真实设备，软件测试不能代替现场验证。
若需恢复，停止 agent，把备份目录中的对应文件复制回原位置；新增模块可留存但不再注册。不要删除 ultra.db，里面是本机测量记录。
本包的 tests/ 为无硬件测试，不启动服务器、不触发真实 BLE、SDK 或灯具发送；可在安装了测试依赖 httpx 的 agent 环境执行 `python -m unittest discover -s tests -p test_ultra_addon.py -v`。
