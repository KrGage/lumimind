# LumiMind 单灯控制模块

把主 agent 最终推荐的“照度 lux”和“色温 K”传给一个 Python 函数，自动生成五通道光配方，并发送到配置的一盏灯。

**情绪页面自动控制请使用新的 `lumimind_emotion_autodim.zip` 更新包。** 它已将“接受建议”按钮接到本模块：点击后程序自动调用，不需要用户运行下面的 Python 示例。下面的函数说明只供维护者参考；完整部署步骤见更新包根目录的《给同事的说明.md》。旧的 `lumimind_single_lamp.zip` 只有底层模块，没有情绪按钮接线。

## 需要给同事什么

自动控制场景给同事发 `lumimind_emotion_autodim.zip`，按其中的安装步骤更新 agent。其 `light_control` 模块保留以下目录：

```text
light_control/
  lumimind_light.py
  light_config.json
  接入说明.md
  runtime/
    LightBridge.exe
    LightBridge.exe.config
    FudanLight.Optics.dll
    Newtonsoft.Json.dll
    Calibrations/
      Room1_Calibration.json
```

不需要安装 Visual Studio、不需要 pip 安装新依赖、不需要启动额外 API 服务，也不需要同时打开师姐的软件。目录必须完整；不能只复制 exe 或 Python 文件。包中不包含主 agent、API 密钥或检测脚本。

请解压到普通可写目录。SDK 运行时可能自动在 `runtime/Logs` 下生成诊断日志；这不是需要额外安装的组件。

同事电脑需要 **Windows x64、Python 3.10 或更新版本、.NET Framework 4.7.2 或更新的 4.x 版本（例如 4.8）**。本包的 SDK 是 Windows/.NET Framework 版本，不能直接在 macOS、Linux 或普通 Linux Docker 容器中运行；安装 .NET 6/8/9 也不等于安装了 .NET Framework。

## 第一步：配置唯一的一盏灯

用记事本打开 `light_config.json`，把 `lamp_ip` 的 `null` 改成实际灯板的 IPv4 地址，例如：

```json
{
  "lamp_ip": "192.168.1.100",
  "udp_port": 26666,
  "room_id": 1,
  "min_ra": 80,
  "iteration_step": 50,
  "solve_timeout_seconds": 60
}
```

**上面的 IP 只是原软件中记录过的示例，不代表已确认是现在这盏灯。** 原包同时记录过 `.100` 和 `.101`，需要现场确认哪一个是目标灯板。这里只填一个地址，不填列表，不使用广播。电脑必须能通过本地网络访问这个地址，灯板需要供电；必要时检查 Windows 防火墙和 Wi-Fi/网线连接。

- `udp_port`：灯板通信端口，原软件为 `26666`。
- `room_id`：灯板配置的房间编号；随包只有房间 1 的标定，默认保留 `1`，它不是灯具数量。
- `min_ra`：SDK 求解时要求的最低显色指数，默认 `80`。没有满足要求的配方时明确报错，不会自行降低标准。
- `iteration_step`：原 SDK 搜索步长，默认 `50`。
- `solve_timeout_seconds`：最多等待配方计算的秒数，默认 `60`。超时不发送。

配置文件可以保存为 UTF-8 或 UTF-8 带 BOM。默认按 Python 文件所在位置查找，与主 agent 当前工作目录无关。

## 维护者参考：底层函数调用（情绪页面已自动完成）

安装器已将整个 `light_control` 文件夹放到项目根目录；单独开发新入口时的结构为：

```text
同事项目/
  main_agent.py
  light_control/
    ...完整文件...
```

主 agent 输出明确的数值后接入：

```python
from light_control.lumimind_light import LightingError, set_light

# 下面两个数值应来自主 agent 的最终结构化推荐。
recommendation = {"illuminance_lux": 300, "cct_k": 4000}

try:
    result = set_light(
        illuminance_lux=recommendation["illuminance_lux"],
        cct_k=recommendation["cct_k"],
    )
    print("调光指令已发送", result["pwm"])
except LightingError as exc:
    print("本次调光未完成：", exc)
```

传数值，不传 `"300 lux"`、`"4000K"` 或 `"300-500"` 这样的字符串。照度必须大于 0，色温为 `1500–20000 K` 范围内的整数；这个范围只是接口允许范围，是否实际可达还取决于灯具色域、输出能力和显色要求。零照度关灯不在这个接口范围内。

**每条最终推荐调用一次。** 不要对模型逐字输出重复调用；每次 `set_light()` 成功都会产生一条新的灯控报文。如主 agent 有重试或并发机制，由主 agent 按推荐 ID 去重、按顺序执行；本小包不跨调用做持久化去重或调度，也不会在 UDP 发送后自动重试。

异步 agent / FastAPI 中不要直接阻塞事件循环：

```python
import asyncio
from light_control.lumimind_light import set_light

result = await asyncio.to_thread(set_light, 300, 4000)
```

如配置放在其他位置，可显式传入路径：

```python
result = set_light(300, 4000, config_path=r"D:\my_agent\lamp.json")
```

## 只计算配方

无需填写灯具 IP，也不连接硬件：

```python
from light_control.lumimind_light import calculate_recipe

recipe = calculate_recipe(300, 4000)
print(recipe["pwm"])        # 顺序 R、G、B、冷白 CW、暖白 WW
print(recipe["predicted"]) # 预计照度、预计色温和色坐标；不是实测值
```

`calculate_recipe()` 永远不发送 UDP。`set_light()` 会先校验目标和配置、调用 SDK，再向唯一的目标地址发送一次。参数无效、没有标定、SDK 无解、超时或响应不合法时不发送；发送报错时执行状态未知，需现场核实。

## 返回结果怎么理解

- `status="calculated"`：仅计算了配方。
- `status="sent"`：电脑已发送 UDP 报文。**这不等于灯具已收到，也不等于照度/色温实测达标。** 原发送协议未提供本包可核验的硬件执行回执，因此 `hardware_confirmed` 始终为 `false`。
- `target`：agent 传入的目标照度、色温。
- `pwm`：SDK 求出的五通道配方，每路整数 `0–4095`。
- `predicted`：由房间标定值估计的输出。`illuminance_lux` 用测得的各通道 Ev 和 PWM 比例混合，存在有效 LUT 时使用 LUT 比例；`cct_k` 由 SDK 正向色温轨迹按 10 K 步长估计。`x/y` 为标定色坐标混合值。
- `solver_ra`：原 SDK 在求解过程中给出的显色指数，属于模型计算值。
- `delta_uv`、`candidate_count`：SDK 原求解器返回的色差和候选数；`delta_uv` 不是灯具实测误差。
- `calibration`：所用房间及原标定时间。

本包实际下发的是原厂 `SolveByCCT()` 给出的 PWM，不修改原厂 DLL。原包 `ComputeFromPwm()` 在随包光谱数据下反算出的绝对照度与标定 Ev 明显不一致，逆 `UVToCCT()` 也出现过错误分支，因此本包预计值采用上述标定混合与正向轨迹方法，不把这些异常反算值当作实测反馈。

## 常见问题

| 情况 | 处理 |
|---|---|
| 提示设置 `lamp_ip` | 填实际单灯地址，原包的两个 IP 不要都照搬 |
| `ModuleNotFoundError` | 保持上述目录结构，从主 agent 项目入口运行；勿只复制 Python 文件 |
| 缺少 `LightBridge.exe` 或 DLL | 重新解压完整最小包，保留 `runtime` 相对位置 |
| 无法启动桥接程序 | 确认 Windows x64、.NET Framework 4.7.2+，检查解压文件是否被系统隔离 |
| 缺少标定或未完整标定 | 检查房间编号及对应标定 JSON，不用其他灯的标定凑数 |
| `SDK solve failed` | 目标可能超出可达范围或不满足 Ra 要求；由 agent 重新推荐，不会偷偷改目标 |
| `status=sent` 但灯没变化 | 核对供电、灯具 IP/房间号、同网段通信、UDP 防火墙；发送成功并不确认接收 |
| 实测照度偏差大 | 核对当前灯具、数量、位置与标定条件，并用你们的监测方式确认 |

## 源码与重建

项目中的 `hardware_bridge/Program.cs` 和 `build.ps1` 保留桥接源码，未放入最小运行 ZIP。同事只运行时不需要这些源文件。维护者可在 Windows PowerShell 中重建：

```powershell
.\hardware_bridge\build.ps1 -SdkDirectory "完整师姐编译包目录"
```

它只复制必要 DLL 和房间 1 标定，并编译桥接程序，不改原始 SDK 或原软件。
